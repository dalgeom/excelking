# excelking (엑셀왕) — 설계 문서

작성일: 2026-06-09
상태: 설계 확정, 구현 계획 대기

---

## 1. 제품 컨셉

한국 사무직의 **반복 엑셀/문서 단순노동**을, **브라우저 안에서 비용 0**으로 없애주는 무료 도구 허브.

- 모든 처리는 **클라이언트(브라우저) 내**에서 수행 → 파일이 서버로 전송되지 않음
- 서버·DB·AI API 없음 → 운영비 0, 트래픽이 곧 애드센스 순수익
- 참고 모델: makejpeg.com (단일 목적 무료 도구 + SEO + 애드센스). 단 excelking은 **여러 도구를 묶은 허브** 구조

**브랜드**: excelking / 엑셀왕. 임시 배포 `excelking.pages.dev`, 추후 `excelking.com` 승계.

## 2. 타겟 사용자

한국 일반 사무직 회사원. 엑셀이 주력 도구이고, 회사 데이터를 외부 웹에 올리는 것을 꺼리는(보안 민감) 집단. 파워쿼리·VBA 같은 내장 기능을 배우기는 귀찮아하는 "가끔 쓰는 다수".

## 3. 핵심 원칙

1. **비용 0**: AI/서버 호출 없이, 코드·알고리즘으로 한 번 만들어두면 무한히 도는 기능만 채택
2. **클라이언트 처리**: 파일은 브라우저를 떠나지 않음 → "서버 전송 안 됨" 문구로 보안 우려 정면 돌파(사무직 핵심 차별점)
3. **웹 도구 검색의도 우선**: "엑셀에서 하는 법(how-to)"이 아니라 "웹 도구로 처리"를 검색하는 작업만 유입구로 선정
4. **하나씩 제대로**: 도구를 한 번에 다 만들지 않고, 순차 출시하며 SEO→트래픽→애드센스 파이프라인을 검증

## 4. 기술 아키텍처

- **SvelteKit + Cloudflare Pages**: git 커밋·푸시 → 자동 재배포 빌드
- **백엔드 없음**: DB·서버·인증 전무
- 핵심 라이브러리(전부 클라이언트):
  - 엑셀 읽기/쓰기: **SheetJS (xlsx)**
  - PDF 파싱(표 추출): **pdf.js** (텍스트·좌표 추출) + 자체 표 재구성 로직
  - PDF 조작(향후): **pdf-lib**
  - 차트(대시보드): **Chart.js**
  - 이미지 처리(향후): canvas API

## 5. 사이트 구조 (SEO 설계)

```
/                  허브: 도구 카드 그리드
/excel-compare     두 엑셀 명단 비교·대조      [1번 출시]
/excel-split       조건별 시트/파일 분리        [2번]
/pdf-to-excel      PDF 표 → 엑셀 추출 (유입 간판) [3번]
/excel-merge       엑셀 합치기 (수요 보조)        [4번]
/excel-dashboard   엑셀 → 자동 대시보드 (차별화 간판) [5번]
```

- 각 도구 = 독립 URL + 독립 타이틀/메타 = 각각 별도 검색 유입구
- 도구 페이지 하단마다 **"사용법 + FAQ + 관련 팁"** 텍스트 콘텐츠 → 내부 링크로 도구끼리 순환

## 6. 도구 라인업과 역할

| 도구 | 역할 | 수동으로? | 엑셀 내장? | 웹 검색의도 |
|------|------|----------|-----------|------------|
| **두 엑셀 비교·대조** | 파이프라인 검증용 1번 | vlookup 지옥 | 함수 알아야 | 중간 |
| **조건별 분리** | 보조 도구 | 필터+저장 노가다 | VBA 필요 | 중간 |
| **PDF 표 → 엑셀** | ★유입 간판(트래픽) | 복붙 시 표 깨짐 | 없음 | 강함 |
| **엑셀 합치기** | 수요 보조 | 소량은 가능 | 파워쿼리 있음 | 약함(how-to) |
| **자동 대시보드** | ★차별화 간판(체류·입소문) | 차트 수작업 | 가능하나 번거로움 | 약함(검색X) |

**두 간판의 분업**:
- PDF추출 = **유입 간판** — 검색에서 트래픽을 *끌어옴*
- 대시보드 = **차별화 간판** — 끌려온 사람을 *붙잡고 입소문*. 다른 도구로 정리한 데이터를 "시각화해볼까?"로 잇는 내부 순환의 종착점

## 7. 출시 순서 (유동적)

```
1번 비교·대조 → 2번 조건별 분리 → 3번 PDF추출(유입간판) → 4번 합치기 → 5번 대시보드(차별화간판)
```

**핵심 전략**: 구현이 쉽고 정확도 리스크가 없는 **비교·대조**를 1번으로 삼아, *사이트 골격 → SEO 콘텐츠 → 애드센스 승인* 전 과정을 빠르게 한 바퀴 검증한다. 검증 후 난이도 높은 **간판(PDF추출)에 화력 집중**. (순서는 운영 중 데이터에 따라 바뀔 수 있음)

## 8. 1번 도구 상세 스펙 — 두 엑셀 명단 비교·대조

**문제**: 두 명단(예: 회원명부 A vs 출석부 B)을 대조해 일치/불일치/차이를 찾는 작업. 현재는 vlookup·조건부서식을 알아야 하고 수동은 실수투성이.

**기능**:
1. 파일 A, 파일 B 각각 업로드 (.xlsx/.xls/.csv)
2. 비교 기준 열(키 컬럼) 선택 — 예: "사번", "이름", "이메일"
3. 결과 3분류 표시:
   - A에만 있음
   - B에만 있음
   - 양쪽 모두 있음 (옵션: 나머지 열 값이 다른 행 하이라이트)
4. 각 분류를 화면 미리보기 + 엑셀로 다운로드
5. 전 과정 브라우저 내 처리, "파일은 서버로 전송되지 않습니다" 문구 노출

**기술**: SheetJS로 두 파일 파싱 → 키 컬럼 기준 Set/Map 비교 → 결과 시트 생성 → 다운로드. 결정론적, 정확도 100%, AI 0원.

## 9. 애드센스 전략 ⚠️

- **승인의 함정**: 버튼만 있는 도구 페이지는 "콘텐츠 빈약"으로 **승인 거절**됨. 따라서 각 도구 페이지의 "사용법·FAQ·팁" 텍스트는 **SEO용 + 애드센스 승인용**으로 필수 요소(설계에 내장)
- 광고 배치: 도구 결과 영역 아래 + 콘텐츠 문단 사이. 도구 동작을 가리지 않게
- 한국어 단가는 낮으므로 **도구 수 × 트래픽**으로 노출 면적 확보

## 10. 수익 모델

- 1차: **Google AdSense** 단일. 비용 0 구조라 트래픽이 곧 순수익
- 유료/구독은 도입하지 않음(비용 0 알고리즘 도구이므로 불필요)

## 11. 범위 밖 (Out of Scope)

- **HWP 변환**: 한글 포맷이 폐쇄적 바이너리라 브라우저 라이브러리로 제대로 안 됨 → 서버 필요 → 비용 0 원칙과 충돌. 채택 안 함
- **AI 기반 요약/분석**: API 비용 발생 → 채택 안 함. 대시보드도 알고리즘(통계·차트)으로만 구현
- **서버 사이드 처리·대량 배치**: 클라이언트 메모리 한계를 넘는 초대용량 파일은 비대상
- **OCR(스캔본→텍스트)**: 정확도·속도 한계로 1차 범위 제외(향후 재검토)

## 12. 리스크

| 리스크 | 대응 |
|--------|------|
| PDF 표 추출 정확도(표 깨짐) | 1번이 아닌 3번으로 배치, 정형 표부터 지원하며 점진 개선 |
| 애드센스 승인 거절(콘텐츠 빈약) | 도구마다 사용법·FAQ·팁 콘텐츠 필수 내장 |
| 엑셀 합치기류의 약한 검색의도 | 유입구는 검색의도 강한 도구로, 합치기는 보조로 격하 |
| 대용량 파일 브라우저 부하 | 처리 전 행/용량 가이드 표시, 점진 처리 |

## 13. 로드맵

1. **MVP (1번)**: 사이트 골격(허브+공통 레이아웃) + 비교·대조 도구 + 콘텐츠 → 배포 → 애드센스 신청
2. **2번**: 조건별 분리 추가
3. **3번**: PDF 표 추출(유입 간판) — 화력 집중
4. **4번**: 엑셀 합치기
5. **5번**: 자동 대시보드(차별화 간판)
6. **고도화**: 도메인(excelking.com) 구매·연결, SEO 강화, 도구 추가
